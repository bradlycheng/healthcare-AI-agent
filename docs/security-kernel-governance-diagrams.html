Security Kernel Governance Diagrams

Four focused views for Warden 2.0: transition diagram, invariants diagram, gates diagram, and audit diagram. These diagrams separate what moves, what must never break, who enforces it, and how proof is recorded.

How To Read This

Use these diagrams after the state diagram. The state diagram shows where things live. This page shows how things move, which laws must hold, which gates enforce them, and what the audit trail should prove.

TransitionsAllowed movements between states.
InvariantsLaws that must always remain true.
GatesWhere rules are enforced in code.
AuditPHI-free proof of decisions and side effects.
Hospital metaphor Transitions are hallway movements. Invariants are hospital laws. Gates are nurses, pharmacists, lab techs, records clerks, and security desks. Audit is the receipt book that records the check without writing private chart details.

Invariants Diagram

Invariants are the laws. If one breaks, the kernel has a real bug, even if the happy path still works.

Authority

Server-Created Only

No client, LLM, RAG, or HL7 note can create grants, trust, or output permission.

Tools

No Grant, No Tool

Every tool call requires live grant, allowed tool, schema, and policy.

Data

No Unguarded Execute

SQL, HL7 parse, token restore, RAG, and calculators have deterministic gates.

State

No Stale Authority

Memory resolves context only; grants expire; parse IDs are same-session and single-use.

Proof

No PHI Audit

Audit records reason codes and counts, not raw question, HL7, FHIR, SQL, or token maps.

Invariant Why It Exists Expected Failure Mode
No LLM output creates authority. LLMs are tainted text processors, not policy engines. Deny, ignore, or treat as evidence only.
No client JSON creates clinical truth. Browser payloads can be tampered with. Ignore/reject client patient, observations, FHIR, status, trust, or summary fields.
No stale reference widens scope. Memory can be old, ambiguous, or attacker-influenced if mishandled. Clarify or deny; create a fresh grant for every turn.
No failed request commits memory. Attackers can force failures to poison future context. Skip memory commit on failure, denial, timeout, interruption, stale state, or clarification.
No guessed token restores PHI. Tokens are visible strings that attackers can copy or invent. Redact unless current request, live grant, output field, and record match.

Gates Diagram

Gates are the actual staff checkpoints. A rule without a gate is just a wish. Each gate should have a clear input, a decision, and an audit event.

Gate Owns Blocks Audit Signal
Warden Tool permission, schema, command-token checks, subject checks. Unknown tools, extra fields, missing grant, wrong subject, unsafe tool text. Tool allow/deny decision with PHI-free reason and field-type counts.
SQLGuard SQL AST safety, table/column allowlists, row caps, note policy. DDL/DML, comments, PRAGMA, ATTACH, blocked tables, note reads without grant. SQL allowed/denied category, no raw SQL in canonical audit.
HL7Guard HL7 shape, caps, note policy, SQL-like note denial. Malformed ORU, missing MSH/PID/OBX, oversized fields, SQL-like clinical text. Segment counts, denial reason, no raw HL7.
TokenGuard PHI token restoration. Guessed, stale, wrong-request, RAG-injected, or out-of-field tokens. Restore/redaction counts and field types only.
Safe Memory Typed reference state and commit rules. Raw history authority, failed-turn memory poison, expired/wrong-session refs. Commit skipped/allowed reason code.

Audit Diagram

Audit is not the place to store patient facts. It is the place to prove that a gate made a decision and why.

Event

Decision Happens

Endpoint or guard allows, denies, redacts, claims, persists, or skips.

Shape

Safe Payload

Payload uses reason codes, counts, booleans, component names, and categories.

Sanitize

Blocked Keys

Strip question, answer, raw HL7, FHIR, SQL, patient names, DOBs, token maps.

Store

governance_events

Insert request, session, component, action, reason, payload, and time.

Review

Query Audit

Investigate denied attempts, replay, unsafe input, and policy decisions.

Future

Monitor

Alert on denial spikes, replay attempts, token redaction spikes, admin failures.

Bad Audit Payload

Audit invariant: record enough to prove the security decision, never enough to reconstruct the patient record or token-real mapping.
