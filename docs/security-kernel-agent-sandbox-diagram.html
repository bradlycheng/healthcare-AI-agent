Execution Phases

Phase 0 Read-only multi-agent mapping. No edits. Produce bypass list and implementation checklist.
Phase 1 Build broad kernel spine. Route high-risk endpoints through session, grant, audit, and fail-closed gates.
Phase 2 Deepen SQL, HL7, token, RAG, calculator, note, and admin guards.
Phase 3 Add safe memory, result refs, TTLs, reference resolution, and no-commit-on-failure behavior.
Phase 4+ Add bounded dynamic context, then operational hardening, retention, production auth, and legacy cleanup.

Validation Gates

Boundary tests No direct LLM imports outside gateway. No ungated /api/query fallback.
Authority tests No client JSON creates clinical truth. No LLM output creates grants, trust, or permissions.
Guard tests SQL, HL7, token, RAG, calculator, memory, and output policies fail closed.
Audit tests governance_events contains reason metadata but no raw PHI, HL7, FHIR, token maps, or stack traces.
Regression tests Valid query, ORU preview, parse_id persistence, and normal clinical note instructions still work.

Recommended Agent Sequence

1. Start with explorers only Use agents for mapping first because security work needs truth before edits.
2. Lead builds or integrates the Phase 1 spine One owner keeps the kernel model consistent.
3. Workers deepen isolated guards Give each worker a narrow write scope and exact test expectations.
4. Reviewer agent checks bypasses Review every phase for bypass, PHI leakage, unsafe fallback, metadata injection, and stale authority.
